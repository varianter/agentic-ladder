#### Individual

- **Getting started · What to learn:** - Using ready made skills like handoff, ponytail, grill-me, triaging, review, security review
  - Evaulating if skills are needed or not
  - Setting proper permissions (sandboxing, guardrails)
  - Know what model you need to use, when. Blasting frontier models is not the same as max output. 
  - Have control over token limits and usage.  
  - Using Claude, Codex
  - Be curious and open minded. Learn. Experiment. This is important, always.
- **Getting started · Why it matters:** it is not cool to go out of tokens and having to wait hours just because you thought you deserved the max model at max effort
- **Getting good · What to learn:** - Writing own skills
  - Writing efficient skills that has evaluated proven impact
  - talking about when MCP is needed, and when it is not. Mostly it is not for dev enviroment. But MCP is a good tool for some settings and being good at AI means being good at determining this
  - Learning how to use AI in products also
  - Writing sub agents with specific mandates, and how to use them properly
  - Using decision trees specifically and possibly LLM routers
  - Doing proper review that does not make you loose control of the codebase or the mental model. You are the expert. You are responsible. Systems you create have impact on the real world, and speed should not be a reason for bad systems. That is your job as a software engineer. "Bus drivers do not drive over the speed limit even though their managers say they should be efficient at". We need to challenge and help teach management
  - using AI to learn new things as we also develop (tech me skills, review quizes, etc)
- **Getting good · Why it matters:** Using AI is not free, but it shifts the focus on where we use our time.
- **Next level · What to learn:** - Leveraging change in how to work for big impact, instead of just trying to do existing tasks quicker.
  - How to setup

#### Team

- **Getting started · What to learn:** - Sharing skills by experience
  - Installing skills and have established shared settings for Codex / Claude
  - Decide if you want to use the same setup or us individual
  - connect to domain knowledge data sources
  - have rules for how to access data and make sure privacy and security is maintained (read only, do not access customer information)
- **Getting started · Why it matters:** Same setup or individual: Do you know what you do, you can use something else. But prefer using the same setup so established skills and practices are shared, raising the general quality of output
- **Getting good · What to learn:** - Making custom made plugins with integrated established development flow practice for specific teams 
  - Having "AI Team contract". How should we use AI to ensure quality and good collaboration
  - Having specific golden path rules and skills for doing things like debugging, error finding, reviewing, creating change log, handling sprint planning, doing post mortems, doing ADRs. Building project knowledge for lasting agent use, not specific for individuals in the team.
- **Getting good · Why it matters:** Lasting team knowledge that connects knowledge cross individuals, and avoids tacit knowledge. Improve quality output and making sure to focus on proper impactful outcome.
- **Next level · What to learn:** - Setting up software factories in a way that works for that team for that domain, with the quality needed.
  - Shifting left in the development pipeline as to changing how they work as a team, being enabled by AI not for solving same tasks faster, but solving new things better, and getting to use more time at more critical aspects of software engineering.

#### Organization

- **Getting started · What to learn:** - Having proper guidelines for usage, and established practices. 
  - Create structures for learning and experimenting.
- **Getting started · Why it matters:** - Consultants can help with this if we have the proper knowledge and experience. Lots of clients don't know where to start
  - Users will find a way. Shadow AI is more harmful than people experimenting naively with setup teams, as shadow ai for private usage has no control and models train on this data, even when payed private subscriptions.
- **Getting good · What to learn:** - Custom making integration points like skills, plugins, mcps
  - having proper control of data and access.
- **Getting good · Why it matters:** - Extending the organization knowledge and internal best practices continously. Improving a iterative knowledge building for shared common knowledge
  - loosing control of data is easy. Need to have full control, observability, information security to avoid people getting access to more than they should (common access hub can make it go from one person access check to server to server access check where the server has more access than the user)
- **Next level · What to learn:** - Changing structure, decision making, changing collaboration practises
  - Having duplex tools, not only resources for finding information but for doing actions. Changing HR stuff, onboarding users, creating KPI reports, creating slides. One stop shop for discoverable tool usage for users, and guided interactive tours for doing so
  - having own custom made assistants that is highly integrated with they way the business work, instead of using established general solutions such as Claude.ai etc
